# UMAN-ECO Enterprise Lab v2.0 — Test Checklist

A concise checklist for reviewing the public GitHub Pages demonstration.

> **Academic prototype:** UMAN-ECO is an educational simulator using sample data and modeled results. It is not a production service, certified carbon-accounting tool, or live cloud-management platform.

## Deployment

- [ ] The GitHub Pages site loads at its published URL.
- [ ] The homepage, styles, scripts, and sample data load without errors.
- [ ] Navigation and asset links work from the GitHub Pages repository path.
- [ ] The site is accessible in a private/incognito browser session.

## Interface and Navigation

- [ ] The **U · E** logo is centered within its box, without clipping or wrapping.
- [ ] All six sections open: **Overview**, **Quick Simulator**, **Carbon Intelligence**, **GreenOps Decision Lab**, **Evidence & Audit**, and **Methodology**.
- [ ] Layout, controls, and tables remain usable on desktop and mobile screens.
- [ ] UMAN-ECO and its relationship to the **UMAN Framework Family** are identified clearly.

## Simulator and Carbon Intelligence

- [ ] The default sample workloads and dashboard metrics display correctly.
- [ ] Changes to energy, efficiency, electricity price, and other scenario inputs update the results.
- [ ] Reset and scenario-sharing functions work as intended.
- [ ] Provider filters, scenario comparisons, and embodied-carbon options update the displayed information.
- [ ] Sample CSV import, CSV export, and sample-data restore work correctly.
- [ ] Invalid or unsupported imported data produces a clear error.
- [ ] Assumptions and modeled values are distinguishable from measured data.

## GreenOps and Audit Simulation

- [ ] Recommendations display estimated carbon, cost, and operational impacts.
- [ ] Policy settings affect recommendation eligibility as expected.
- [ ] Simulated approval and rejection actions respect the selected role.
- [ ] Decision history appears in **Evidence & Audit** and can be exported.
- [ ] Local history can be cleared using the provided control.
- [ ] The interface makes clear that no live infrastructure changes occur and audit records are browser-local, not immutable.

## Documentation and Public Safety

- [ ] `README.md` and `METHODOLOGY.md` describe the prototype's scope, assumptions, and limitations.
- [ ] Academic-only and non-production notices are visible to website visitors.
- [ ] The repository contains no credentials, secrets, confidential information, or real customer data.
- [ ] No production readiness, standards certification, guaranteed savings, or support commitment is implied.
- [ ] The site runs without significant browser-console errors.
